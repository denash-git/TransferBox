# TransferBox — Генеральный план архитектурного рефакторинга (v4 Python Edition)

Документ фиксирует фундаментальные правила, архитектурные слои и пошаговый план полного перевода базы TransferBox на модульный Python с сохранением надежности, визуальной строгости и безопасности.

---

## 🏛 Базовые архитектурные принципы

### 1. Архитектура со строгим разделением слоев (Clean / Layered)
Вся бизнес-логика отделена от интерфейсов. Консольное меню (TUI) и Telegram-бот являются равноправными «клиентами» и не содержат собственной логики управления системой.

```
┌────────────────────────────────────────────────────────────────────────┐
│                      Слой интерфейсов (Presentation)                   │
│   ┌────────────────────────────────┐  ┌────────────────────────────┐   │
│   │   TUI (Terminal UI)            │  │   Telegram Bot             │   │
│   │   (prompt_toolkit + rich)      │  │   (aiogram 3.x)            │   │
│   └───────────────┬────────────────┘  └─────────────┬──────────────┘   │
└───────────────────┼─────────────────────────────────┼──────────────────┘
                    ▼                                 ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   Слой сервисов (Service / Domain Layer)               │
│   ┌─────────────────┐ ┌──────────────────┐ ┌────────────────────────┐  │
│   │   UserService   │ │  ServiceManager  │ │    NetworkService      │  │
│   │ (CRUD, ссылки,  │ │ (Caddy, sing-box,│ │ (UFW, порты, BBR, SSH, │  │
│   │  подписки)      │ │  Mieru, bot)     │ │  DNS)                  │  │
│   └────────┬────────┘ └────────┬─────────┘ └───────────┬────────────┘  │
│            │                   │                       │               │
│   ┌────────┴────────┐ ┌────────┴─────────┐             │               │
│   │  BackupService  │ │DiagnosticsService│             │               │
│   │ (AES-256, zip,  │ │ (CPU/RAM/Disk,   │             │               │
│   │  восстановление)│ │  логи, speedtest)│             │               │
│   └────────┬────────┘ └────────┬─────────┘             │               │
└────────────┼───────────────────┼───────────────────────┼───────────────┘
             ▼                   ▼                       ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   Инфраструктура & Адаптеры (Infrastructure)           │
│   ┌────────────────────────────────┐  ┌────────────────────────────┐   │
│   │ ConfigRepository (JSON, .env)  │  │ SystemExecutor             │   │
│   │ Безопасный ввод-вывод конфигов │  │ (LinuxExecutor / Mock)     │   │
│   └────────────────────────────────┘  └────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────────┘
```

* **100% переиспользование:** Добавление пользователя, включение протокола или проверка Caddy выполняется одинаково и ботом, и TUI.

---

### 2. Строгие модели данных (Pydantic / Dataclasses)
* Полный отказ от ненадежных сырых словарей (`dict`) при работе с `users.json` и `instance.env`.
* Все сущности описываются классами:
  * `User`, `VlessConfig`, `MieruConfig`, `NaiveConfig`
  * `ServerConfig`, `ServiceStatus`, `BackupMetadata`
* Автоматическая валидация: неверные порты (например, >65535), некорректные IP или домены перехватываются еще до записи на диск.

---

### 3. Абстракция системных вызовов (`SystemExecutor`)
* **Безопасность выполнения:** вызовы `systemctl`, `ufw`, `caddy` инкапсулированы в адаптер с таймаутами и обработкой исключений.
* **Поддержка двух режимов:**
  * `LinuxExecutor`: выполняет реальные вызовы на сервере Linux.
  * `MockSystemExecutor`: эмулирует системные команды в памяти, позволяя локально запускать и тестировать 100% логики на Windows/macOS без прав root.
* **Соблюдение правил `GEMINI.md`:**
  * Caddy: обязательный `validate` перед мягким `reload`; сброс `reset-failed` при аварийном статусе.
  * SSH: открытие нового порта в UFW строго **до** перезапуска sshd, проверка `ss -tlnp` и мгновенный откат при ошибке.

---

### 4. Встроенное автоматическое тестирование (Pytest)
* `tests/unit/`: мгновенные тесты генераторов ссылок (VLESS, Naive, Mieru), валидаторов моделей и криптографии бэкапов.
* `tests/services/`: проверка бизнес-логики сервисов с `MockSystemExecutor`.
* `tests/safety/`: тесты на нерушимость критических сценариев безопасности (SSH rollback, Caddy reload safety).

---

### 5. Дизайн TUI: Строгий, компактный и приятный (`prompt_toolkit` + `rich`)
* **Никаких номеров пунктов меню:** выбор осуществляется навигацией клавишами `↑` / `↓` и клавишей `Enter`.
* **Аккуратные иконки и эмодзи:** лаконичные маркеры разделов (📦, 👥, ⚡, 🛡️, 🌐, 🤖, 💾, ⚙️).
* **Сетка 60 символов:** сохранение фирменной горизонтальной центрированной сетки `(cols - 60) / 2`.
* **Статусные индикаторы:** чистые Unicode-точки (`●` зеленая для активных, `●` красная для неактивных).
* **Безопасные диалоги:** маскирование паролей (`***`) при вводе пароля архива бэкапа.

---

### 6. Структурированное логирование (Observability)
* Модуль `logging` с ротацией в `/var/log/transferbox/app.log`.
* Пользователь в консоли видит лаконичное и понятное сообщение об ошибке, а в файл пишется детальный traceback для быстрой диагностики.

## 📋 Пошаговый план перехода (Roadmap)

```
Этап 1: Ядро и Адаптеры ──► Этап 2: Сервисы ──► Этап 3: TUI UI-Kit ──► Этап 4: Экраны TUI ──► Этап 5: Тесты и VPS
```

### Этап 1: Инфраструктурный слой и Модели (Core & System)
- [ ] Описать Pydantic-модели (`User`, `ProtocolConfig`, `ServerConfig`, `ServiceStatus`).
- [ ] Реализовать `core/system/executor.py` (`SystemExecutor`, `LinuxExecutor`, `MockExecutor`).
- [ ] Реализовать `core/system/config_repo.py` (потокобезопасная загрузка/сохранение `instance.env` и `users.json`).
- [ ] Написать базовые unit-тесты моделей и файловых операций.

### Этап 2: Слой сервисов (Business Logic Services)
- [ ] `UserService`: добавление/удаление/переключение пользователей, генерация VLESS/Naive/Mieru ссылок и подписок.
- [ ] `ServiceManager`: безопасный контроль systemd (Caddy, sing-box, Mita, Bot) с валидацией Caddyfile.
- [ ] `NetworkService`: управление UFW, смена SSH-порта с откатом, включение BBR.
- [ ] `BackupService`: создание зашифрованных zip-архивов, восстановление, ротация pre-update бэкапов.
- [ ] `DiagnosticsService`: системные метрики (CPU/RAM/Disk), Speedtest, чтение логов служб.
- [ ] Покрыть все сервисы тестами с `MockExecutor`.

### Этап 3: TUI UI-Kit на `prompt_toolkit` + `rich`
- [ ] Базовый класс экрана `BaseScreen` со строгой 60-символьной сеткой и центрированием.
- [ ] Виджет меню без номеров: навигация `↑`/`↓` + `Enter`, активный курсор `›`, подсветка строки.
- [ ] Виджеты индикаторов (`●` зеленый/красный), информационных плашек и разделителей `═` / `─`.
- [ ] Компонент безопасного ввода текста и паролей `read_input` / `read_secret`.

### Этап 4: Экраны консольного интерфейса (TUI Screens)
- [ ] `MainMenu`: сводка статуса служб, кнопки разделов.
- [ ] `UsersMenu`: список пользователей, карточка пользователя, показ ссылок и генерация QR-кода прямо в терминале.
- [ ] `ProtocolsMenu`: управление параметрами VLESS, NaiveProxy, Mieru.
- [ ] `BotMenu`: настройка токена, Chat ID, запуск/остановка бота.
- [ ] `DiagnosticsMenu`: мониторинг ресурсов, просмотр логов Caddy / sing-box, Speedtest.
- [ ] `BackupMenu`: создание бэкапа с паролем, список архивов, восстановление.
- [ ] `SettingsMenu`: порт SSH, BBR, обновление панели.
